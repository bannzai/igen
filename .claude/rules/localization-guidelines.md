# ローカライゼーションガイドライン

このドキュメントは、igen プロジェクトの翻訳（ローカライゼーション）に関するガイドラインを定義します。

## 基本情報

- アプリの基本言語は**英語**（US 向け「Dear Socrates」モードがそのまま英語 UI になる）
- 第一市場は日本。ja 翻訳は機械的な直訳ではなく、「幻想的で、ちょっと怪しい占いの館」の世界観に合う日本語にする
- コード上のコメントは**日本語**（メインの開発者が日本人だから）
- `.xcstrings` の方式を採用します。ファイル名は `Localizable.xcstrings` です

## 基本ルール

- TextなどのSwiftUI標準のローカライズ対象になるものや、`String(localized:)` に書く文字列は**英文で書いてください**。英語圏ユーザーにはそのまま表示されます
- 英文は英語圏の文化やテンションになぞって作成してください
- **コードを書くときは `Text("English sentence")` の上に `// ja:` から始まるコメントで日本語訳を書いてください**

## `// ja:` コメントの書き方

- `// ja:` コメントは「**アプリのUI翻訳が必要な箇所**」のみに付ける
- `Text()` や `String(localized:)` の上に書く
- enum ケースの説明コメントやプロパティの説明コメントには `// ja:` を付けない（これらは翻訳対象ではない）
- 改行は`\n`ではなく、空行としてコメントに残す

```swift
// ja: 偉人に聞く
Text("Ask the Greats")
```

## 固有名詞と機能名の扱い

- アプリ内の固有名詞や機能名が文中に出てくる場合は、必ずText()で埋め込む
- 固有名詞は引用符で囲む。英語であればシングルクォート（`''`）、日本語であれば（`「」`）

## ローカライズ対象外のデータ

- 格言・ことわざの本文・**原文**・出典・偉人名・返書本文は、名言 DB / バックエンドから受け取る**データ**でありローカライズ対象ではない。`Localizable.xcstrings` に入れず、受け取った値をそのまま表示する
- 各言語での見せ方（訳文をどの言語で返すか）はバックエンド側の責務とする。原文はどのロケールでも改変せず併記する（出典の信頼性の要件。documents/PROJECT.md の UI 要望 6 参照）

## 翻訳の追加方法

1. SwiftUIのコード内で `String(localized:)` または `Text()` で英語の文言を記述
2. アプリの翻訳が必要な箇所はコメントで日本語訳を記載。アプリの翻訳以外のコメントは `ja:` 無しで
3. `Localizable.xcstrings` に該当の英語文言のエントリーを追加し、jaのlocalizationのみを追加

## 注意事項

- コーディング段階では**日本語（ja）の翻訳のみ追加**してください
- 他の言語は追加しないでください。後で翻訳AIのAPIを使用して、英語原文と日本語訳を参考に他言語への翻訳を一括で行うため、この段階では日本語のみで十分です
- 医療を想起させる語（therapy, counseling, diagnosis / セラピー, カウンセリング, 診断, 処方）を UI 文言に使わない（App Store 審査と医療該当性の両面。documents/PROJECT.md のリスク 2 参照）
