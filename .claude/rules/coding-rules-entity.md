# コーディングルール（Entity/データ層）

このドキュメントは、Entity（Firestore ドキュメントのデコード先・AppStorage 等）やデータ層に関するコーディングルールを定義します。Firestore のスキーマとアクセス方針は `.claude/rules/firestore-rules.md` を参照してください。

## Firestore ドキュメントの方針

- Firestore ドキュメントのデコード先は `Codable` な struct で定義する。スキーマの単一の真実は `documents/design/db-schema.md` で、変更時は必ず両方を同期する
- 新しく追加するプロパティは Optional で宣言する（過去に書き込まれたドキュメントにはそのフィールドが存在しないため。デコード失敗でデータが読めなくなる事故を防ぐ）
- クライアント側でドキュメントを組み立てて書き込まない（書き込みは Functions 経由。firestore-rules.md 参照）

## ドキュメントコメント

### struct, class, enum には必ずドキュメントコメント（`///`）を追加する

- struct, class, enum の宣言の直前に `///` で始まるドキュメントコメントを記載する
- そのデータ型が何を表し、どのように使用されるかを明確に説明する

## 命名規則

### 変数名には通常、動詞（editing, selected等）をつけない

- Feature名自体がその役割を表しているため、変数名は名詞のみで良い
- どうしても必要な場合はコメントで理由を明記する

### AppStorage のkey名と変数名は一致させる

- `UserDefaults+.swift` で定義されたkey名と、`@AppStorage` で使用する変数名を同じにする
- 理由: key名と変数名が一致していることで、どのUserDefaultsキーを使用しているか一目で分かる

## 文字列とローカライゼーション

### ローカライズ結果の文字列を永続化しない

- `String(localized:)` を評価した結果の文字列を永続化しない。保存後にロケールを切り替えても保存済み文字列は再評価されず、履歴や設定表示が旧ロケールのまま残るため
- 永続化するのは安定したキー・enum・元データとし、表示時に現在のロケールで `Text` / `String(localized:)` に変換する
- 表示用の文字列をコードで組み立てる場合も、ハードコードされた文字列ではなく `String(localized:)` を使用する（Preview のサンプルデータも同様）
- 例外: 格言・ことわざの本文・原文・出典はローカライズ対象ではなく**データ**。サーバー（名言 DB）から受け取った値を加工せずそのまま保持・表示する（原文の改変は出典の信頼を壊す）

## プロパティ設計

### 保存側で不要な値をnilにする処理は本質的ではない

- enumやフラグで使用するプロパティが変わる場合、保存側で「使わない方をnilにする」処理は不要
- 保存側はそのままの状態で保存し、使用側で enum や flag を switch して適切なプロパティを使用する

### enum に表示用の文字列やアイコンを返すプロパティは持たせない

- 表示ロジックは enum ではなく View に書く（coding-rules-view-ui.md と同一原則のデータ層側の適用）
