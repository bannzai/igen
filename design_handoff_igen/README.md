# Handoff: 偉言(イゲン)— 偉人からの返書アプリ

## Overview
悩みや今日のできごとを書くと、それに適した偉人が星座線アバターで現れ、出典付きの格言・ことわざで励ましてくれる iOS アプリ「偉言」のプロトタイプ一式。チャットではなく「人生相談への返書」フォーマット。カウンセリング・セラピーは名乗らない(励まし・自己肯定のエンタメ寄り)。全8画面+演出を実装済み。

## About the Design Files
このバンドルの HTML ファイルは **HTML で作られたデザインリファレンス**です(見た目と挙動を示すプロトタイプであり、そのまま出荷するコードではありません)。タスクは、これらのデザインをターゲットのコードベース(SwiftUI 想定。未定なら iOS ネイティブ = SwiftUI を推奨)の既存パターン・ライブラリで**再現実装**することです。

- `偉言 Prototype.dc.html` … 全画面の動くプロトタイプ(ロジック・演出込み)
- `偉言 Variations.dc.html` … 採否検討用のバリエーション集(アバター画風/返書レイアウト/図解カード/入力UI/英語版)
- `igen-data.js` … サンプルデータ(偉人・返書・履歴・星図)。データモデルの参考
- `ios-frame.jsx` … プレビュー用の iPhone フレーム(実装対象外)

## Fidelity
**High-fidelity**。色・タイポグラフィ・余白・文言・アニメーションはすべて意図した最終形。ピクセル単位で再現すること。ただし「偉言 Variations」内の案は探索用であり、採用が確定しているのはプロトタイプ本体の画風・レイアウトのみ。

## デザイン原則(実装時も厳守)
- 世界観:「幻想的で、ちょっと怪しい占いの館」。深い藍〜紫の星空が全画面背景。ダークテーマ固定
- 偉人は**星座線アバター**(点=星+細い光の線)で統一。写実イラスト・写真は使わない
- 格言・出典テキストは高コントラストで可読性優先
- 医療・診断を想起させる語(セラピー、カウンセリング、処方など)を UI 文言に使わない
- 英語モードでテキスト量が 1.5 倍になっても破綻しないこと(固定高さ禁止、折返し前提)

### 2. 回答演出(リチュアル)
- **Purpose**: 送信後、星が集まり星座線で偉人が描き上がる
- **フェーズ**(初回 / 2回目以降短縮):
  1. 散らばった星(ランダム座標)を表示 … 開始 140ms / 90ms
  2. 星がアバター座標へ収束(transform transition 1.9s cubic-bezier(.22,1,.36,1), 星ごとに delay (i%7)*90ms)… 2.3s / 1.1s
  3. 星座線が描画(stroke-dashoffset len→0, .8s ease, 線ごとに delay i*130ms)… 4.4s / 2.1s
  4. 偉人名リビール(「セネカ」24px Mincho +「◯◯が、あなたの空に現れました」)→ 返書へ自動遷移 … 6.2s / 3.1s
- 待機文言「星々が、ことばを探しています…」(明滅)。「スキップ」ボタン常設(下部, ゴースト)
- 背景は rgba(5,6,18,.45) のスクリム

### 3. 返書(レター)
- **Layout**: ヘッダー(とじる/タイトル「あなたへの返書」/共有)+ スクロール本文(padding 8 24 44)。各ブロックは igenReveal(opacity+blur(6px)+translateY(10px)→0, .8〜1s)で 0.15s 刻みの stagger 出現
- **本文構成(順序固定)**:
  1. 日付(11px 中央)
  2. 話者ブロック: 星座線アバター130px + 偉人名(Mincho 600 20px, ls .15em)+ 肩書き—時代(11px)
  3. **図解カード**(話者が特定できない場合のみ、アバターの代替): border rgba(232,201,122,.3), radius 16。見出し「図解 — ことばのしくみ」。「たとえ」→「意味」→「使いどころ」の3ノード縦フロー。ノード間は金のグラデ縦線(1×16px)。「意味」ノードのみ Mincho+強めの枠で強調
  4. ひとこと(14px/2.1)
  5. **格言**: Mincho 600 24px/2, 中央, 上下に金のヘアライン(rgba(232,201,122,.25)), text-shadow で淡い金のグロー
  6. **対訳ブロック**(外国語由来のみ): bg rgba(12,12,40,.65), radius 12。ラベル「原文(ラテン語)」(10px, ls .2em, #e8c97a)+ 原文(Georgia italic 15px)/ 区切り線 / ラベル「日本語訳」+ 訳文 13px
  7. 意味と文脈: ラベル(10px ls .25em #e8c97a)+ 本文 14px/2.1
  8. 結び: Mincho 15px/2.2 +「— ◯◯ より」右寄せ(話者なしの場合は「— 偉言 より」)
  9. **出典ブロック(信頼の根拠・装飾でなく情報)**: border 1px rgba(232,201,122,.35), radius 12。ヘッダー帯「出典」(bg rgba(232,201,122,.12))。2カラム grid(72px+1fr, 12px): 出典 / 原題(italic, ある場合のみ) / 原文言語 / 成立
  10. ボタン: 「共有カードを作る」(金グラデ primary)+「とじる」(ゴースト)

### 8. セーフティ
- トリガー: 入力に深刻ワード(死にたい/消えたい/自殺/傷つけ/リストカット/生きていたくない 等)を検知したとき。**返書は生成しない**
- トーン: 静かで誠実。星空は保つが演出は抑制(スクリム rgba(4,5,14,.78)、きらめき最小)
- 構成: 静かな一つ星 / 見出し「たいせつなお話を、ありがとうございます」(Mincho 18px)/ 本文(13px/2.1, 「偉言は励ましのアプリで、専門の支援をお届けすることはできません」)/ 窓口カード3件(いのちの電話 0570-783-556、よりそいホットライン 0120-279-338(24時間・通話無料)、まもろうよ こころ(厚労省))/ 注記「このご相談への返書はお送りしていません。」/「ホームにもどる」
- 窓口はタップで発信(tel:)。**電話番号・受付時間はリリース前に必ず最新情報を確認すること**

## Interactions & Behavior
- ナビフロー: ホーム→(送信)→演出→返書→共有 / ホーム→記録→返書(とじる→記録に戻る)/ ホーム→星図→プロフィール→返書
- 送信ロジック: 空入力=無効(opacity .45)→ 深刻ワード検知=セーフティ → 無料枠消費済み=ペイウォール → それ以外=演出開始
- 演出は初回リッチ(約6.2s)・2回目以降短縮(約3.1s)+スキップ常設(毎日使うテンポを守る)
- 背景スターフィールド: 常時。星95個の明滅(sin波, 個別位相)+ 紫の霧3枚がゆっくり横流れ + 5〜11s間隔の流れ星(金のグラデ軌跡)。iOS では低負荷の Canvas/Metal/SpriteKit 相当で
- 返書本文は各ブロック stagger リビール(blur+fade+上昇, 0.15s刻み)
- トースト: 下部中央ピル(金背景, 1.8s で消滅)
- 音声入力: マイクボタンで listening 状態(金枠+「聞いています…」明滅)。実装は SFSpeechRecognizer 等

## State Management
- `screen`: home | ritual | letter | history | atlas | share | paywall | safety
- `draft`(入力中テキスト), `letterId`(表示中の返書), `from`(letter の戻り先: home/history)
- `freeUsed`(当日の無料枠消費, 日次リセット), `rituals`(演出短縮判定), `phase`(演出フェーズ 0–3), `profileId`(星図シート), `listening`, `toast`
- データ: 返書 = {id, person?, date, concern, oneliner, quote, original?, origLang?, meaning, closing, source{work, detail, origTitle?, lang, year}, diagram?{metaphor, meaning, usage}}。偉人 = {id, name, kana, era, title, bio, points[[x,y]…], lines[[i,j]…]}(座標は 0–100 正規化)。`igen-data.js` 参照

## 実装時の注意
- コンテンツはトップから 58px のセーフエリア(ステータスバー/Dynamic Island)を確保済み。SwiftUI では safeAreaInsets に従うこと
- 格言・出典データは監修必須(原文・訳・出典の正確性がプロダクトの信頼の根幹)
- セーフティ検知はプロトタイプでは単純な語句マッチ。本実装ではより堅牢な分類を用い、検知時は返書を生成しないこと
